# Schema Review: Consolidation + Deprecation Candidates

This is a working review of baseline schemas generated by `schema-gen`. The goal is to identify likely consolidations and deprecations before we add detailed descriptions and tighten constraints.

## Decision Status (2026-02-22)
High-confidence merge candidates were consolidated on 2026-02-22. Data files were merged and legacy schema files were marked as deprecated.

## High-Confidence Merge Candidates
1. `dialogues_v1.json` + `aria_dialogues_v1.json`
   - Merge into `dialogues_v1.json` with a `dialogue_source` or `category` field if needed.
   - Deprecate `aria_dialogues_v1.json`.

2. `effects_v1.json` + `status_effects_v1.json` + `effects_config_v1.json`
   - Consolidate into `effects_v1.json` with top-level sections:
     - `effects`, `status_effects`, `config`.
   - Deprecate `effects_config_v1.json` and `status_effects_v1.json` if no loader needs them separately.

3. `skills_v1.json` + `abilities_v1.json` + `psychic_abilities_v1.json`
   - Consolidate to `abilities_v1.json` with a `category` field (`skill`, `ability`, `psychic`).
   - Deprecate `skills_v1.json` and `psychic_abilities_v1.json` if possible.

### Deprecation Marked (Pending Consolidation)
Completed:
- `aria_dialogues_v1.json` -> `dialogues_v1.json`
- `effects_config_v1.json` -> `effects_v1.json`
- `status_effects_v1.json` -> `effects_v1.json`
- `skills_v1.json` -> `abilities_v1.json`
- `psychic_abilities_v1.json` -> `abilities_v1.json`

## Medium-Confidence Merge Candidates
1. `walls_v1.json` + `floors_v1.json` + `lights_v1.json`
   - Combine into `map_elements_v1.json` or `map_tiles_v1.json`.
   - Pros: shared rendering attributes.
   - Cons: different loaders may expect separate files.
   - Decision: **Defer consolidation.** `lights` includes spawn rules and different fields; `walls`/`floors` are pure tile defs. Keep separate until a unified map-element loader exists.
   - Legacy deprecation: Once `map_elements.json` is adopted, mark `walls_v1.json`, `floors_v1.json`, `lights_v1.json` as deprecated.

2. `structure_templates_v1.json` + `microstructures_v1.json` + `structure_generation_v1.json`
   - Combine into `structures_v1.json` with sections for templates, microstructures, and generation rules.
   - Decision: **Defer consolidation.** Data shapes are distinct and `structure_generation` is test-tool only. Revisit if/when generation tools are unified.

3. `render_config_v1.json` + `themes_v1.json` + `keyboard_config_v1.json` + `auto_explore_config_v1.json`
   - Combine into `ui_config_v1.json` with dedicated sections.
   - Decision: **Defer consolidation.** Loaded by different subsystems; keyboard config integration is still TODO in UI. Keep separate for now.

## Low-Confidence (Needs Further Study)
1. Worldgen cluster:
   - `terrain_config_v1.json`, `biome_profiles_v1.json`, `travel_config_v1.json`,
     `world_generation_integration_v1.json`, `generation_config_v1.json`,
     `map_features_v1.json`, `dynamic_events_v1.json`.
   - Might remain separate but should share common conventions and ids.
   - Decision: **Keep separate.** These are consumed by distinct systems (terrain forge adapter, biomes, travel, feature registry, events). Revisit once worldgen integration is unified.

2. Loot/spawn cluster:
   - `spawn_tables_v1.json`, `loot_tables_v1.json`, `expanded_spawn_tables_v1.json`.
   - Unclear if there are distinct consumers or overlapping concerns.
   - Decision: **Keep separate; deprecate expanded.** `spawn_tables` and `loot_tables` are used by different systems. `expanded_spawn_tables` has no data file.

## Proposed Deprecations (Conditional)

- `skills_v1.json` and `psychic_abilities_v1.json` (if merged into `abilities_v1.json`)
