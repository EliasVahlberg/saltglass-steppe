# VERA Batch F Prompt: Event System → Reactions

**Execute VERA Batch F: Replace the GameEvent system with VERA reactions. Work directly on main.**

Read `docs/development/architecture_refactor/VERA_FULL_MIGRATION.md` — this is Batch F.

**Goal:** Replace `process_events()` and the `GameEvent` enum with typed VERA reactions. Effects trigger reactions directly — no intermediate event queue.

**Current implementation:**

`process_events()` drains `event_queue: Vec<GameEvent>` in a loop (max 10 iterations for cascades):
```rust
for event in events {
    LootSystem.on_event(self, &event);
    QuestSystem.on_event(self, &event);
    self.handle_event(&event);
}
```

`GameEvent` variants include: `EnemyKilled`, `ItemPickedUp`, `LevelUp`, `AdaptationGained`, `TurnEnded`, `AriaInterfaced`, `VoidExposureChanged`, `CrystalResonanceChanged`, and others.

Systems react to events:
- `LootSystem.on_event(EnemyKilled)` → drops loot at death position (uses RNG)
- `QuestSystem.on_event(*)` → updates quest progress for kill/collect/position objectives
- `handle_event(*)` → logging only

**Migration approach:**

1. **Replace event listeners with `collect_reactions()` match arms.** The reaction infrastructure from Phase 3 already exists (`run_reactions`, `collect_reactions`, `TraceSource::Reaction`). Currently `collect_reactions` is a no-op. Fill it in:

   ```rust
   fn collect_reactions(&mut self, effect: &Effect, ctx: &QueryContext, rng: &mut ChaCha8Rng) -> Vec<ReactionOutput> {
       let mut results = Vec::new();
       match effect {
           Effect::Combat(CombatEffect::Kill { enemy_idx, enemy_id, x, y }) => {
               results.push(reaction_loot_drop(enemy_id, *x, *y, ctx, rng));
               results.push(reaction_quest_on_kill(enemy_id, ctx));
           }
           Effect::Item(ItemEffect::AddToInventory { item_id }) => {
               results.push(reaction_quest_on_collect(item_id, ctx));
           }
           Effect::Player(PlayerEffect::SetPosition { x, y }) => {
               results.push(reaction_quest_on_position(*x, *y, ctx));
           }
           Effect::Player(PlayerEffect::GainXp { .. }) => {
               // Level-up check is already in the apply arm
           }
           _ => {}
       }
       results
   }
   ```

2. **Convert LootSystem to a reaction function:**
   ```rust
   fn reaction_loot_drop(enemy_id: &str, x: i32, y: i32, ctx: &QueryContext, rng: &mut ChaCha8Rng) -> ReactionOutput
   ```
   Returns `ItemEffect::SpawnOnMap` effects. The loot table lookup and RNG rolls happen here.

3. **Convert QuestSystem to reaction functions:**
   ```rust
   fn reaction_quest_on_kill(enemy_id: &str, ctx: &QueryContext) -> ReactionOutput
   fn reaction_quest_on_collect(item_id: &str, ctx: &QueryContext) -> ReactionOutput
   fn reaction_quest_on_position(x: i32, y: i32, ctx: &QueryContext) -> ReactionOutput
   ```
   Each returns `QuestEffect::Progress` effects.

4. **Convert handle_event logging to Presentation effects.** The logging in `handle_event` becomes `Presentation::LogMessage` returned by the reactions or auto-generated by the apply arms.

5. **Remove the event system infrastructure:**
   - Delete `event_queue: Vec<GameEvent>` from GameState
   - Delete `emit()`, `drain_events()`, `process_events()`, `handle_event()`
   - Delete `GameEvent` enum (or keep it temporarily if anything still references it)
   - Delete `TurnPhase::ProcessEvents` — reactions run automatically after each dispatch
   - Remove `LootSystem` and `QuestSystem` `impl System` — they become reaction functions

**RNG ordering — this is the critical constraint:**

Currently, loot drops happen at end-of-turn time (in `process_events`). Moving them to reactions means they fire immediately when `CombatEffect::Kill` is applied — which is during the player's attack, not at end of turn. This changes when RNG is consumed for loot rolls.

Options:
- **Option A: Accept the RNG ordering change.** Loot drops happening at kill time is arguably more correct. But it breaks seed determinism with existing saves/DES scenarios.
- **Option B: Defer loot reactions to end of turn.** Collect kill effects during the turn, run loot reactions in a dedicated phase after all actions. Preserves RNG ordering.
- **Option C: Keep LootSystem as a special case.** Everything else becomes reactions, but loot stays event-driven until a clean break point (e.g., next save version bump).

**Recommend Option A** if no DES scenarios depend on specific loot drop outcomes with fixed seeds. Check by running all DES scenarios after the change — if they pass, the ordering change is safe. If any fail, fall back to Option B.
